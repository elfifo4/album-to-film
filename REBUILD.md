# Rebuilding the working environment from scratch

Use this after a cleanup, on a new machine, or when a bug turns up in a finished film and the tools
are gone. Everything the pipeline produces can be regenerated, as long as the small set of files
listed under "What must be kept" still exists.

## What must be kept

These cannot be regenerated. Back them up before any cleanup.

| Keep | Why |
|---|---|
| The source folder with the captures | The only originals. Read-only for the pipeline. |
| `config/project.json` | Points at the source folder. |
| `review/overrides.json` | Every decision made by hand: corners, rotations, enhancement level, exclusions, film picks, star scores. |
| `editorial/event_ranges.json` | Which photographs belong to which chapter, and the chapter order. |
| `editorial/scores.json` | First-pass emotional scores. Without it every photo scores 3 and the selection changes. |
| `editorial/story_order.json` | The order of photographs set by hand. |
| `editorial/music.json` and the song file it names (in `assets/`) | The song and the moments pinned to photographs. |
| `renders/final/` | Finished films. |

Photograph ids are derived from the content of each source file, so the saved decisions still match
after a rebuild as long as the source files are unchanged.

## What can be deleted and regenerated

| Path | Regenerated by | Time on the original machine |
|---|---|---|
| `.venv/` | the install commands below | about a minute |
| `models/face_detection_yunet_2023mar.onnx` | the download command below | seconds |
| `catalog/`, `reports/`, `work/` | `rebuild` | under a minute |
| `processed/`, `previews/` | `rebuild` (the restore step) | about 6 minutes for 207 photographs |
| `timeline/` | `rebuild` | seconds |
| `renders/drafts/` | `rebuild --render` | about 1 minute per 2 minutes of 1080p film |

## Steps

Requirements on the machine: Python 3 (3.14 was used), FFmpeg, and `git`.

1. Get the code, if the folder is gone:

```bash
git clone https://github.com/elfifo4/album-to-film.git
```

2. Put the kept files back at the paths in the table above.

3. Create the environment with the exact versions that were used:

```bash
python3 -m venv .venv
```

```bash
.venv/bin/python -m pip install -r requirements.lock
```

4. Download the face model (used for orientation checks and for aiming camera moves):

```bash
curl -L -o models/face_detection_yunet_2023mar.onnx https://github.com/opencv/opencv_zoo/raw/main/models/face_detection_yunet/face_detection_yunet_2023mar.onnx
```

5. Regenerate everything and render the films:

```bash
.venv/bin/python -m album_to_film rebuild --render
```

6. Confirm the source folder was not touched:

```bash
.venv/bin/python -m album_to_film verify
```

The review page is available again with `.venv/bin/python -m album_to_film review`.

## What `rebuild` runs

`ingest` → `analyze` → `restore` (all photographs, with the saved decisions) → `dedupe` → selection
for each film → `timeline` for each film → with `--render`, `render` for each film at 1080p into
`renders/drafts/`.

Every stage is resumable: running `rebuild` again only redoes what is missing or out of date.

## Things that can differ after a rebuild

- **Library versions.** `requirements.lock` pins them. Installing from `requirements.txt` instead may
  pull newer versions, which can shift a crop or a colour by a hair.
- **Without the face model**, orientation falls back to earlier hand-made rotations and the saved
  decisions, and camera moves aim at the centre of each photograph instead of at faces.
- **Duplicate groups** are recomputed. Exclusions already saved in `review/overrides.json` stay.
- **Without `editorial/scores.json`** the automatic part of each film's selection changes; photographs
  pinned In or Out by hand stay.
